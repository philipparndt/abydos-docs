Abydos

A terminal-first IDE for AI and cloud development.

The terminal is not a strip at the bottom of an editor. It is where the work happens — shells, tmux windows, agents, a program running in a pod — and the editor, the debugger and the cluster arrange themselves around it. Native AppKit: no web view, no Electron, no subscription.

Download the latest release Source on GitHub

macOS 14 or newer, Apple silicon. Signed with a Developer ID and notarised.

The two claims

Everything else here is an editor doing what editors do. These two are why it exists.

Debug your program where it actually runs

A launch configuration with one extra key builds for the cluster's architecture, pushes the binary into a development pod and runs it there — about a second, against the minutes an image build and a rollout cost. The pod has the real chart's config, its secrets, its service account and its sidecars, so the program finds what production would give it.

Then press debug. It stops on your breakpoint in the pod, in your own sources, because the binary was compiled on this machine and its debug information names these files. A JVM is held suspended until you attach, so a worker cannot finish before you arrive.

Agents as sessions, not as a sidebar

An agent session is a PTY the app owns rather than something a view owns. It can be hidden, shown again, or handed over for manual takeover, and its process keeps running throughout.

Results come back over MCP as typed data — file, line, severity, detail — arriving as the work proceeds, so a click goes to the line.

And the rest of an IDE

Eleven pages, one for each part of it. Every picture below is the app doing the thing the page beside it claims, on a project from the examples repository that anybody can clone.

Editor

A persistent rope, highlighting scoped to what is on screen, and a parser allowed to land a frame late. 0.013 ms a keystroke in a 100,000-line file.

Terminal and agents

A real PTY with tmux's own windows as the tabs, and agent sessions the app owns rather than a view — so hiding one does not kill it.

Run and debug

What a project can run is found rather than configured, and the program stops on your breakpoint where it actually runs — a pod in the cluster, in about a second.

Git

One tree on ⌘2 and two pages that open at the size they are given — with a real branch left behind before anything destructive runs.

Pull requests

Reviewed here rather than in a browser: whole-file diffs with a language server pointed at them, and ticks that die when the author pushes.

Secrets

A .env opens unreadable because the screen might be being shared, SOPS decrypts in place without touching a disk, and the file says whether git can see it.

Languages

Twenty-four highlighted and folded, and which of them are served, run, debugged and taken to a cluster — with what each needs on your machine.

Getting around a project

One field for projects, branches and every command; the packages the project depends on beside its own files; and lists that are worked through rather than read.

Diagrams

PlantUML, Mermaid and draw.io beside the source that makes them — and draw.io as its whole editor, not a viewer.

3D modelling

OpenSCAD, go3mf and Cadova models in Swift, each shown beside the code that describes it — and never a cube that is not your model.

Themes

Four themes with a daylight half each, photographed eight times on one project — and a ninth is a JSON file you drop in a folder.

Three decisions do most of that: a persistent rope whose interior nodes sum bytes, UTF-16 units and newlines; highlighting scoped to the bytes on screen; and a parser that runs off the main thread and is allowed to land a frame late. The rope is authoritative for text, the parser only for colour.

Building it yourself

# Xcode's Swift, not whichever one is first on the PATH.
git clone https://github.com/philipparndt/abydos.git
cd abydos
make          # build the .app and launch it
make test     # the suite
make dev      # debug build, in the foreground, logs on the terminal
