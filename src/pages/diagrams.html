Diagrams

A .puml, a .mmd and a .drawio open with the drawing beside the source, and a fence in a markdown file is drawn where it stands. Three tools, one pane, and one Export ▸ menu.

Mermaid, without a browser to install

Mermaid is JavaScript, and every command-line form of it is a headless Chromium. So the real Mermaid is here instead — 3.6 MB of it, in a web view inside the app — against the 2.16 GB a container would have cost. Nothing to install and nothing to start.

What it hands back is flattened before it is shown or written. Mermaid's output is written for a browser: a stylesheet with some shapes attached, labels in HTML, arrowheads as references to shapes a renderer is expected to place. The pane draws through CoreSVG and the exported PNG is rasterised by WebKit, so anything left in the file that needs a browser draws one picture on screen and a different one in the file somebody sends on. Every style is resolved onto the shape it paints, and the two renderers are held to differing over less than a tenth of the page.

Mermaid's own layout is in the bundle; the others are separate packages and none is shipped. Asked for one of them Mermaid does not refuse — it lays the diagram out its own way and says nothing — so one line under the drawing says which layout was asked for and what was drawn instead.

draw.io, which is the whole editor

Not a viewer. The shapes are dragged in the tab, with draw.io's own palette and its own stencils, and the document stays the app's: the tab's edited dot, ⌘S, the close-without-saving prompt, auto-save and the file watcher all go on working. Dirty state is immediate, because the graph model's own change event is what is listened to rather than draw.io's autosave timer.

The file is written back the way it came. A compressed document stays compressed and a plain one stays plain. Undo stays draw.io's — ⌘Z reaches the web view and mxGraph's undo manager handles it — which is also why a .drawio opens as the drawing with no source half at all.

PlantUML

A .puml is drawn by PlantUML, which is a JVM and is the one of the three that needs something on the machine — installed, or out of an image the project names. It is kept warm rather than started per diagram. It is also served, by plantuml-lsp, so a .puml gets completion and problems like any other file with a server behind it.

Whatever is drawn, the same three rules

In the colours the window is wearing

A diagram is drawn in the app's theme rather than in the tool's default white, so a dark window does not hold one white rectangle. A file that sets its own colours keeps them, and is told in one line under the drawing that it did.

Exported as SVG or PNG, and no more

SVG for anything that will be looked at or scaled, PNG for anything pasted into something that cannot read a drawing. One menu across all three tools — in the preview and in the tree.

PlantUML never fails on a diagram: one it cannot parse comes back as a picture of the complaint. Right for a preview, and wrong for an export that would write diagram.png, report success, and leave a picture of an error message in somebody's repository. So both routes are asked for the complaint as well as the picture.

A pane with no picture says why

A diagram pane is a picture or it is a sentence: nothing while a tool runs, nothing for a file with nothing drawable in it yet, nothing for a diagram the tool refuses. The message is wrapped rather than elided — what to install, or what the parser expected and on which line.

And in a markdown file

A fenced block is drawn where it stands, by whichever of the three the fence names. The Export ▸ menu is offered over a markdown file only when there is actually a diagram in it.

Nothing here is this app's reading of a format. Mermaid is Mermaid, draw.io is draw.io, and PlantUML is the same jar it always was — what Abydos decides is when to run them, what to do with what they hand back, and what to say when they will not. The same division as the 3D modelling.
