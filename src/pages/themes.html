Themes

Three themes, each with a daylight half and a dark one. The same project, the same file, the same window size — so what differs between these pictures is only the colour.

⌘, → Appearance, which is the first page and holds the editor's colours and the terminal's together — one thing to look at, so one place to decide it. It takes effect on the windows that are already open: the palette is swapped underneath them rather than applied to the next one.

Two questions rather than one list. Theme is which palette — Abydos, Blue or Dracula — and Light or dark is how light it should be, with System as the third answer to the second question rather than an entry in the first. Three by three, and the six that are not a deferral are below.

Every picture on this page was taken by make theme-shots, and the colours listed under each are read out of the scheme the app ships — abydos.json, blue.json, dracula.json.

Abydos

Abydos Light

Settings: Abydos + Light Terminal scheme: abydos, at daylight weights What Abydos + System resolves to in the day

Not the dark one inverted. Amber on near-black works because the amber is the light in the room; the same amber on paper is a highlighter pen. So the warmth moves into the surfaces instead — unbleached paper rather than white — the ink is a dark brown, and the accent is amber taken down to where it can be read on paper.

Daylight

Settings: Blue + Light What Blue + System resolves to in the day

Not the dark palette inverted. A light theme wants more contrast in the text and less in the surfaces, or every panel edge shouts — so the greys sit close together and the colours do the separating. The editor is the one white surface on the screen, which is what makes it the thing you look at.

Dracula

Settings: Dracula + Dark Terminal scheme: Dracula's own sixteen, unchanged The one palette here that is not ours

People arrive with this one rather than discover it here, so the values are upstream's rather than adjusted to taste, and the six accents keep the roles Dracula assigns them: pink for keywords, green for functions, purple for constants and numbers, cyan for types, orange for parameters, yellow for strings. Only the roles this app has and Dracula does not — a git status, a fold placeholder — are placed here.

System

System is not a palette but a deferral, and it belongs to the second question rather than the first: it follows the Mac's own light and dark setting without touching which theme you chose. Abydos plus System is amber after dark and warm paper by day; Blue gives dusk and daylight; Dracula gives Dracula and Alucard. It changes while the app is running, so a machine that switches at sunset switches the editor with it.

One of your own

A scheme is a file, and each of the three above is one: abydos.json, blue.json, dracula.json. Two sections — app for the editor and its chrome, terminal for the terminal — and every colour a light/dark pair.

Yours goes in ~/.config/abydos/schemes, which is read at every start. Dropping a file in there is the whole of adding a palette, and one carrying the same id as a shipped scheme replaces it — so the amber one can be adjusted rather than copied. 

{
  "id": "nord",
  "title": "Nord",
  "app": {
    "windowBackground": { "light": "#F7F8FA", "dark": "#1A1C21" },
    "syntax": { "keyword": { "light": "#0033B3", "dark": "#D8926B" } }
  },
  "terminal": {
    "ansi": { "black": { "light": "#2B2D30", "dark": "#1D1F21" } }
  }
}

Abbreviated: every role, every syntax kind and all sixteen ANSI colours have to be there, both halves of each pair, each #RRGGBB. A file missing one is not loaded at all, and the key and the file are named in ~/Library/Logs/Abydos/schemes.log — a theme applied nine-tenths of the way is diagnosed by staring at a window and wondering. Three keys may be left out, each with a stated derivation rather than a silent default.
